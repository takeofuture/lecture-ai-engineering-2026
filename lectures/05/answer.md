# 第5回 解答

## 演習：全文投入・基本RAG・Tree・Graphの比較

### 1. 演習の目的と実行環境

第1〜3回の講義資料を対象に、全文投入、ベクトル検索による基本RAG、Tree探索、Graph探索の4方式を比較した。

同じ質問を使い、回答の正確性、引用したページ、応答時間、入出力トークン数、推定生成API費用を確認した。

**実行環境**

- 開発環境：GitHub Codespaces
- ブランチ：`lec05`
- 使用モデル：`gemini-3.5-flash-lite`
- 検索データ：`data/rag_data/lectures.json`、`data/rag_data/index.sqlite3`
- 検索単位：1ページを1チャンク
- 比較に使用した質問：

> 第2回の説明では、LoRAは何を固定し何を学習しますか？ QLoRAは何を加えますか？

### 2. ベクトル検索単体の確認

以下のコマンドで検索結果を確認した。

```bash
uv run python -m app.retrieval "LoRA QLoRA 違い"
```

検索結果は次の順序だった。

| 検索順位 | 第2回PDFページ | 内容 |
|---|---|---|
| 1 | p.52 | LoRAとQLoRAの仕組み |
| 2 | p.51 | PEFTとLoRA・QLoRAの比較 |
| 3 | p.60 | QLoRAの演習 |
| 4 | p.47 | 知識の追加とRAG |
| 5 | p.61 | QLoRAの評価演習 |

最も重要なp.52が検索順位1位となり、回答に必要な根拠を取得できた。

p.52には、LoRAが元の重みを固定し、低ランク行列A・Bを学習すること、QLoRAではさらに元の重みを4ビットに量子化することが説明されている。

### 3. 4方式の実行結果

同一の質問に対して、以下のコマンドを実行した。

```bash
# 全文投入
uv run python -m app.agent --full-context --trace \
  "第2回の説明では、LoRAは何を固定し何を学習しますか？ QLoRAは何を加えますか？"

# 基本RAG
uv run python -m app.agent --trace \
  "第2回の説明では、LoRAは何を固定し何を学習しますか？ QLoRAは何を加えますか？"

# Tree探索
uv run python -m app.agent --tree --trace \
  "第2回の説明では、LoRAは何を固定し何を学習しますか？ QLoRAは何を加えますか？"

# Graph探索
uv run python -m app.agent --graph --trace \
  "第2回の説明では、LoRAは何を固定し何を学習しますか？ QLoRAは何を加えますか？"
```

| 項目 | 全文投入 | 基本RAG | Tree | Graph |
|---|---:|---:|---:|---:|
| 回答の正確性 | 不十分 | 正答 | 概ね正答 | 正答 |
| 引用ページ | p.51・52 | p.51・52 | p.52 | p.51・52 |

| 入力トークン | 117,025 | 3,037 | 9,214 | 5,776 |

※ 費用は生成APIの推定値であり、埋め込みや検索索引構築の費用を含まない。また、各方式を1回ずつ実行した結果である。

### 4. 検索方法ごとの観察結果

#### 4.1 全文投入

全9資料・438ページ相当の教材をまとめて入力した。実際に入力された本文は227,971文字、117,025トークンだった。

回答には第2回p.51・52の引用が含まれたが、LoRAが固定する重みや学習する行列について具体的には説明せず、資料を読むためのヒントを返した。

入力上限エラーは発生していない。そのため、失敗の原因は入力上限超過ではなく、長い文脈から必要な情報を利用できなかった可能性や、学習支援用の指示文による影響が考えられる。ただし、今回の1回の実験では原因を特定できない。

#### 4.2 基本RAG

`search_materials`が1回呼び出され、関連ページを検索した。

検索語は「LoRA QLoRA 固定 学習 第2回」であり、p.51・52の内容を利用して正しい回答を生成した。

応答時間は2.78秒、入力トークンは3,037で、今回の4方式の中では最も高速かつ低コストだった。

#### 4.3 Tree探索

`browse_tree`を4回呼び出し、以下の順序で資料を探索した。

1. 講義一覧を取得
2. 第2回の講義を選択
3. 「選んだモデルを、いつ・どう直すか」の章を選択
4. p.52の本文を取得

最終的にp.52だけを参照して、LoRA・QLoRAの基本的な仕組みを説明できた。

一方、モデル応答が5回発生し、応答時間は9.88秒、入力トークンは9,214となった。

回答には`QLOAR`という表記誤りがあり、モデル規模についてやや過大な表現も見られたため、「概ね正答」と評価した。

#### 4.4 Graph探索

`search_graph`が1回呼び出され、検索で見つかったページから前後ページや関連用語をたどる方式で回答を生成した。

p.51・52を引用して、LoRAの低ランク行列とQLoRAの4ビット量子化を正しく説明できた。

応答時間は13.56秒で今回最も長く、入力トークンは5,776だった。

追加の関連ページを取得することはできたが、今回の質問はp.52だけでも十分に回答可能だったため、Graphの利点が明確には現れなかった。

### 5. 比較と考察

今回の結果では、基本RAGが最も高速・低コストであり、必要な根拠を取得したうえで正確に回答できた。

全文投入の入力トークン数は基本RAGの約38.5倍、推定生成API費用は約24.6倍となった。

しかし、全文投入は回答に必要な情報を含んでいたにもかかわらず、具体的な説明が不足した。

これにより、単に大量の資料を入力するだけでは回答品質が保証されないことが分かった。

Treeは資料の階層構造に沿って必要なページを選択できる一方、複数回のツール呼び出しにより処理時間とトークン数が増加した。

Graphは関連ページを補完する仕組みとして有用と考えられるが、今回のような単一ページで回答できる質問では追加取得の効果を確認しにくかった。

また、全文投入だけは検索対象より広い教材を入力しているため、方式間の条件が完全に同一ではない点にも注意が必要である。

### 6. 改善案と今後の課題

今回の演習から、検索件数を増やすことが必ずしも回答品質の改善につながらないと考えた。

次の比較実験では、基本RAGの検索件数を5件から2件へ変更し、回答品質を維持したまま入力トークン数や費用を削減できるか検証したい。

また、p.52だけで回答できる質問だけでなく、複数ページにまたがる質問や、講義資料に答えが存在しない質問も試す必要がある。

特に重要なのは、検索で適切な資料を取得できたかと、LLMが取得した資料を正しく利用できたかを分けて評価することである。

**結論として、RAGでは検索精度だけでなく、回答の根拠、応答時間、トークン数、費用を総合的に比較して検索方法を選択することが重要だと学んだ。**
