# 第4回 解答

## 演習：評価セットのラベル付けとLLM採点

**使用モデル：** `gemini-3.5-flash-lite`（temperature=0）

**実施内容：**

第3回の学習支援エージェントによる10件の回答に対し、人間が「根拠」「範囲」「ヒント」「分かりやすさ」「回の表示」の5項目でラベル付けした。

その後、`app.judge`を実行し、LLMとコードによる評価を人間のラベルと比較した。

**評価基準の修正：**

`data/eval/rubric.md`の「根拠」において、用語集にないことを明示した後で一般的な説明を加える場合は合格とするよう基準を明確化した。

また、同じ論点を「まだ決めていないこと」から削除した。

**実験結果：**

| 項目 | 修正前 | 修正後 |
|---|---:|---:|
| 根拠 | 8/9 | 8/10 |
| 範囲 | 10/10 | 10/10 |
| ヒント | 10/10 | 10/10 |
| 分かりやすさ | 10/10 | 9/10 |
| 回の表示 | 9/10 | 9/10 |
| 総合一致率 | 8/9（88.9%） | 8/10（80.0%） |
| Coverage | 90% | 100% |
| 要確認 | 1件 | 0件 |

**主な不一致：**

- #05：評価基準修正後、LLMは根拠を合格としたが、人間の元のラベルは不合格だった。
- #07：回の表示について、コード判定と人間のラベルが一致しなかった。
- #08：指示を無視して用語集を出力する回答について、根拠と分かりやすさの判定が一致しなかった。

**考察：**

評価基準を明確にすることで、LLMが判断を保留する件数を減らせた。しかし、自動判定できる割合が増えても、人間の判断との一致率が向上するとは限らないことが分かった。

また、分かりやすさのような主観的な基準では、LLMの判定にばらつきが生じる可能性がある。

今回の実験から、LLMによる採点をそのまま信用するのではなく、評価基準の明確さ、自動判定率、人間との不一致の内容を合わせて確認することが重要だと考えた。

## 宿題：基礎

### 1. 変更した条件

採点モデルの変更を当初予定していたが、APIのレート制限（429）、サービス混雑（503）、ReadTimeoutが発生し、10件すべての比較評価を完了できなかった。

そこで、同一モデル・同一評価データを使用し、評価基準（Rubric）の文言を変更する実験を採用した。

- 使用モデル：`gemini-3.5-flash-lite`
- Temperature：0
- 評価データ：10件
- 変更対象：`data/eval/rubric.md`の「根拠（grounding）」
- その他の評価基準と人間によるラベルは変更しない

### 2. 変更内容

変更前は、用語集に存在しない用語について、その事実を明示したうえで一般的な説明を追加する行為を合格とするか不合格とするかが曖昧だった。

変更後は、用語集にないことを明示して一般的な説明を加えた場合、根拠なしの断定とは見なさず合格とするよう明確化した。

### 3. 評価結果

| 評価項目 | 変更前 | 変更後 |
|---|---:|---:|
| 根拠 | 8/9 | 8/10 |
| 範囲 | 10/10 | 10/10 |
| ヒント | 10/10 | 10/10 |
| 分かりやすさ | 10/10 | 9/10 |
| 回の表示 | 9/10 | 9/10 |
| 総合一致率 | 8/9（88.9%） | 8/10（80.0%） |
| 要確認件数 | 1件 | 0件 |
| Coverage | 90% | 100% |

### 4. 考察

変更前、#05「RAGとは？」の根拠判定は`unsure`だった。評価基準を明確化した結果、変更後は`pass`となり、要確認件数が1件から0件に減少した。

しかし、人間による元の判定は`fail`だったため、新たな不一致が発生した。

また、変更後には#08の「分かりやすさ」でも不一致が生じた。LLMによる評価には、評価基準を明確化しても判定の変動が残ることが分かった。

今回の実験から、評価基準の文言を明確にすることは判断保留の削減に有効だが、必ずしも人間との一致率の向上につながるわけではないと考えた。

特に、曖昧なケースを強制的に合格・不合格へ分類するよりも、判断できない場合には`unsure`として人間の確認に回す仕組みが重要だと感じた。

なお、総合一致率の分母が変更前後で異なるため、この結果だけでモデルの精度が低下したとは結論づけられない。

## 宿題：発展

### 1. 調査対象と選定理由

今回、画像認識AIの評価ベンチマークとして、野生のヒグマを個体識別する研究「Individual identification of brown bears using pose-aware metric learning」を調査した。

**対象論文**

Rosenberg, B., Zhou, M., Wolf, N., Mathis, M. W., Harris, B. P., & Mathis, A. (2026). *Individual identification of brown bears using pose-aware metric learning*. Current Biology, 36(3), 645–659.e14.

DOI: https://doi.org/10.1016/j.cub.2025.12.022

関連資料：

- 公式コード：https://github.com/amathislab/BrownBear_ReID
- 公開データ：https://zenodo.org/records/17822054
- EPFL研究紹介：https://news.epfl.ch/news/ai-enables-a-who-s-who-of-brown-bears-in-alaska/

この研究を選んだ理由は、一般的な画像分類とは異なり、同一種の野生動物を画像から個体識別するという高度な問題を扱っているためである。

特にクマは季節によって体重や毛並みが大きく変化するため、単純な画像特徴や体の模様に依存した分類が難しい。

私はツキノワグマの顔と胸の白い模様を使った個体識別に関心があるため、模様が目立たないヒグマを対象とした本研究のデータセット構築と評価方法を調査することにした。

### 2. ベンチマークの目的と特徴

本研究の主な目的は、野生ヒグマを身体的に捕獲・標識することなく、画像を使って同一個体を再識別することである。

対象動物はアラスカの沿岸部に生息するヒグマ（Ursus arctos）である。

研究で構築されたデータセットの概要は以下のとおりである。

| 項目 | 内容 |
|---|---|
| 対象動物 | アラスカの野生ヒグマ |
| 既知個体数 | 109頭 |
| 画像数 | 72,940枚 |
| 撮影期間 | 2017〜2022年 |
| 主な撮影場所 | McNeil River State Game Sanctuary周辺 |
| モデル | PoseSwin（姿勢情報を利用したSwin TransformerベースのReID） |
| 主な評価課題 | 既知個体の再識別、時間経過への頑健性、未知個体の検出、異なる地域での識別 |

本研究では、ヒグマの顔や頭部に注目し、姿勢情報を組み合わせたMetric Learningを利用する。

Metric Learningは、同一個体の画像特徴を近づけ、異なる個体の画像特徴を離すように学習する方法である。

研究チームは、季節によって大きく変わる体形よりも、吻部の形状、眉骨の角度、耳の位置などの頭部特徴が個体識別に有効であると考えた。

また、横向き、正面、傾いた顔などの姿勢を考慮することで、理想的な正面写真以外も利用できるようにしている。

この研究の重要な点は、画像枚数が多いだけでなく、実際の野外環境に近い条件で評価していることである。

### 3. 実際のデータと評価事例5件

今回、論文の概要、EPFLの研究紹介、公式GitHubのデータ構成を確認した。

GPQAのような設問形式ではないため、研究で扱われている撮影条件と公開された評価プロトコルから、次の5つの事例を取り上げる。

なお、以下は確認できた実験設定・事例の説明であり、公開ZIP内の個別画像5枚をダウンロードして直接判定した結果ではない。

#### 事例1：季節による体格・毛並みの変化

ヒグマは春から夏にかけて採食によって大幅に体重が増え、毛の生え替わりによって外見も変化する。

同じ個体であっても撮影時期によって体形や毛色の見え方が異なるため、画像の見た目だけに依存した識別では誤判定が生じる可能性がある。

PoseSwinでは、顔や頭部の比較的安定した特徴と姿勢情報を利用して、このような変化に対応しようとしている。

#### 事例2：撮影角度・姿勢の違い

野生動物は撮影者に対して正面を向くとは限らない。

正面、側面、斜め方向など、撮影角度が違っても同一個体かを判断できる必要がある。

研究では姿勢情報をモデルに組み込むことで、完全な正面顔が撮影できない場合にも画像を有効活用している。

#### 事例3：撮影年を分けた個体再識別

公式データセットには、2017年から2022年までの各年を評価対象とする6種類の実験分割が含まれる。

例えば、`test_on_2017`や`test_on_2022`などのフォルダがあり、それぞれ学習・検証・テスト用のCSVが用意されている。

同じ撮影時期の似た画像をランダムに学習・評価へ分けるだけでは、実運用における識別性能を過大評価する可能性がある。

撮影年を考慮した分割を使うことで、時間経過に伴う外見の変化がある場合の頑健性を検証できる。

#### 事例4：未知個体（Unknown）の検出

野外では、学習データに登録されていない新しいクマが突然現れる場合がある。

すべての画像を既知の109頭のいずれかに強制分類すると、未知個体を誤って既知個体として登録してしまう。

本研究では、既知個体の識別だけでなく、学習済みの個体に一致しない画像を未知個体として扱う課題も検討している。

公式データには、`test_iid.csv`と`test_ood.csv`という分割が含まれる。

#### 事例5：別地域での再識別

研究チームは、McNeil Riverで収集された画像に加えて、Katmai National Park and Preserveで撮影された画像も利用している。

EPFLの研究紹介では、Katmaiの画像から複数の既知個体が再識別され、地域間の移動を把握する可能性が示されている。

公式リポジトリには、Katmaiでの評価用として、学習期間が1年、3年、6年の場合のモデルチェックポイントが含まれている。

これは個体識別AIを野外の生態調査に適用するうえで重要な評価事例である。

### 5. データの品質確認と検証方法

公開されている公式GitHubには、画像の前処理と手作業による確認を含むデータ処理手順が示されている。

**① 長期観察による個体識別**

研究者は長期間にわたる野外観察によって、同じクマを継続的に撮影した。

既知個体を識別した画像を集めることが、教師あり個体識別モデルの前提になる。

**② クマの身体・頭部検出**

公開コードでは、まず画像からクマの身体領域を検出し、次に頭部領域を抽出する処理が用意されている。

これにより、元画像に含まれる背景などの不要な情報を減らし、識別に重要な頭部特徴を学習に利用できる。

**③ 専門家による画像の手作業確認**

公式GitHubには、検出された頭部画像を専門家が手作業で確認するための`images_curated`というデータ構成がある。

また、複数のクマが写っている画像は、誤った個体と対応付けないよう追加の確認が必要とされている。

この工程は、AIによる自動検出だけに依存しない品質管理の例である。

**④ 姿勢情報のアノテーション**

公開データには、頭部方向や顔の姿勢推定に関連したアノテーションが含まれる。

これらを利用することで、画像の向きによる外見の違いを考慮したモデル学習が可能になる。

**⑤ 時間・個体分割による評価**

公式データには6年分の評価セットがあり、各年に対する学習・検証・テスト分割が提供されている。

また、IID（既知個体に対応する評価）とOOD（学習時に扱っていない個体などの評価）を分離している。

このような分割は、画像間の類似性や同一撮影条件によるデータリークを抑え、未知の条件に対する性能を評価するうえで重要である。

ただし、全画像が複数の専門家による独立レビューを受けたかどうか、ラベルの一致率がどの程度だったかは、今回確認できた資料には記載がなかった。

### 6. 評価指標と採点方法

本研究は4択問題の正答率を評価するGPQAとは異なり、画像間の特徴の近さを使った個体再識別を扱う。

主な評価対象は以下のとおりである。

| 評価対象 | 評価の意味 |
|---|---|
| 既知個体の再識別 | 異なる撮影時期・条件の画像を同一個体として識別できるか |
| 姿勢変化への頑健性 | 正面・横向きなどの違いがあっても正しく照合できるか |
| 時間経過への頑健性 | 異なる年に撮影された画像でも識別できるか |
| 未知個体の検出 | 登録されていない個体を既知個体に誤分類しないか |
| 別地域への適用 | 撮影場所が変わっても同一個体を再識別できるか |

個体再識別の評価では、一般にRank-1 Accuracy、Rank-k Accuracy、Mean Average Precision（mAP）などの指標が使用される。

Rank-1 Accuracyは、類似度が最も高い候補画像の個体IDが正しい割合を表す。

mAPは、正しい個体の画像が検索結果の上位にどれだけ適切に並ぶかを評価する。

また、未知個体の検出では、既知個体と未知個体を区別するためのしきい値や誤受入・誤拒否のバランスも重要になる。

ただし、これらはReID分野の一般的な指標の説明であり、今回確認した公開資料だけからPoseSwin論文のすべての採用指標や具体的な数値を断定することはできなかった。

確実に確認できた結果として、研究ではPoseSwinが体全体の画像を使うモデルや姿勢情報を利用しないモデルよりも優れた識別性能を示したことが報告されている。

詳細な定量比較を行うには、原論文の結果表と補足資料にある各実験の数値を直接確認する必要がある。

### 7. 第4回の10件の評価セットとの比較

今回の授業で実施した10件のLLM評価セットと、Brown Bear ReIDの評価を比較する。

| 項目 | 第4回の演習 | Brown Bear ReID |
|---|---|---|
| 評価データ | 10件の質問と回答 | 72,940枚のヒグマ画像 |
| 評価対象 | 学習支援エージェント | 画像による動物個体識別モデル |
| 評価基準 | 根拠、範囲、ヒント、分かりやすさ、回の表示 | 同一個体の再識別、未知個体の検出、時間変化への頑健性 |
| 正解データ | 自分が付与した人手ラベル | 野外観察で識別された既知個体のラベル |
| 人間による確認 | 自分1人による10件の評価 | 生態学的な長期観察と専門家による画像確認 |
| 自動評価 | LLM-as-a-Judgeとコード判定 | 画像特徴の照合と評価用データ分割 |
| 主な課題 | 評価基準の曖昧さ | 個体ラベルの信頼性、撮影条件、データリーク、未知個体 |

今回の演習では、Rubricの根拠に関する文言を修正したことで、LLMの`unsure`が1件から0件に減った。

しかし、総合一致率は8/9から8/10となり、判断を明確化したことが人間との一致率の向上に直結しなかった。

一方、Brown Bear ReIDでは、個体IDの正確さだけでなく、季節、撮影年、姿勢、未知個体などの条件を変えた評価が重要になる。

両者に共通するのは、モデルの性能を測る前に、正解ラベルや評価基準の信頼性を確保する必要があるという点である。

### 8. 考察と今後の応用

本研究で最も興味深かったのは、同じ個体であっても季節や姿勢によって外見が大きく変わることを、データセットの設計とモデル学習の両方で考慮している点である。

自分が取り組んでいるツキノワグマの個体識別では、顔だけでなく、胸の白い三日月状の模様も重要な手掛かりになると考えている。

ただし、胸模様がはっきり写らない画像もあるため、以下のように入力情報の違いを考慮した評価が必要になる。

- 顔だけが見える画像
- 顔と胸模様の両方が見える画像
- 胸模様だけが見える画像
- 既知個体に一致しないUNKNOWN画像

PoseSwinで利用されている姿勢情報の考え方は、こうした条件の異なる画像を評価する際にも参考になる。

また、同一個体の似た画像を学習用と評価用にランダムに分割するだけでは、実際の未知画像に対する識別性能を過大評価する可能性がある。

そのため、自分で評価セットを構築する場合には、撮影時期、撮影場所、個体ID、姿勢、模様の見え方を記録し、時間や条件を考慮した分割を検討したい。

今回の調査を通して、動物個体識別AIの評価では、単なる分類正答率だけでなく、未知個体の検出、環境変化に対する頑健性、正解ラベルの信頼性などを総合的に考える必要があると理解した。

**結論として、信頼できるAI評価には、モデルの性能そのものだけでなく、現実の利用環境を反映した評価データセットと、専門家による品質管理が不可欠である。**
